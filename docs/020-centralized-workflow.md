# 020 中央协调工作流：减少人工操作的改造设计

日期：2026-11-21。本文是本次实现与验收依据；与 014、018、019 的交互流程冲突时以本文为准，原有隔离与不可绕过的安全约束仍然有效。

## 1. 问题与目标

原始原则见 `000-philosophy.md`：尽可能少占用人的注意力。当前“启动服务 → 检查环境 → 启用 Worker → 申请计划 → 审批 → 每任务附资料 → 人工交接 → 重试再审批”把协调责任交给了人。

本次不是删除多任务调度，也不是放开 Worker 权限，而是把操作合并到可信协调服务。目标体验：

> 用户交代目标、项目和资料；主 Agent 建立任务图；人确认一次目标授权；协调服务准备环境、分发资料、按依赖推进；只有业务决策、失败处理、越界操作和最终交付需要人。

### 可验证的修改目标

| 编号 | 修改目标 | 验收标准 |
| --- | --- | --- |
| G1 | 一次计划确认完成本地执行准备 | 新计划确认在同一操作内检查环境、快照资料、启用受限运行时、授权任务图；不再另去运行环境页解锁 |
| G2 | 普通重启不丢失有效授权 | 指纹、有效期及安全状态不变时，经重新检查复用原启用授权；禁用、过期、环境改变、清理不确定时不能复用 |
| G3 | 资料声明一次，服务负责分发 | 建计划时显式列出绝对文件路径；审批页面显示路径；确认后一次快照共享给未完成成员，不再逐任务上传/输入 ID |
| G4 | 低风险阶段自动交接 | 新计划中非人工里程碑的 artifact 节点，满足结构化完成条件后自动接收并解锁下游；明确标注“系统交接”，不是人工验收 |
| G5 | 人工操作不二次申请同一授权 | 已登录控制台确认启动/恢复/重试/计划启动后直接执行相应授权，保留版本、预算、指纹与幂等检查；MCP 仍不能自批 |
| G6 | 面板围绕目标与异常组织 | 默认展示任务图/计划；人工控制只显示当前可执行动作；健康环境折叠，细节放诊断区；最终验收可同时结束已全部验收的计划 |
| G7 | 保留预算和恢复边界 | 准备阶段确定未发送模型时有界退避恢复；不确定执行、业务失败、发布和人工停止不自动重放或解锁 |
| G8 | 不改变旧计划的授权含义 | 未声明新工作流的旧计划继续人工交接；旧授权不会自动获得新的资料访问或交接权限 |

## 2. 授权边界

当前 MCP 连接不能证明某段文本就是可信的人类批准。因此不把 `source: manual`、任务文本、文件内容或主 Agent 的“用户已经同意”当作审批凭据。保留首次可信控制台/CLI 的目标确认，但合并重复步骤。后续如宿主提供可验证的会话授权凭据，可再接入，不在本次伪造。

控制台已具备本地会话、Origin、CSRF 和 admin RPC 隔离。新增直接人工控制只允许这条可信管理通道调用；公开 MCP 继续只能申请授权。禁止通过降低鉴权、自动点击审批或给 Worker admin token 实现简化。

一次目标确认包含：项目、成员范围、依赖、资源、预算、到期时间、自动交接规则、人工里程碑、资料路径，以及运行环境准备的说明。运行环境不能通过真实检查时返回一个具体阻塞原因，不假装启动成功。

运行时启用属于当前项目而非单个节点：同项目其他已获有效授权的待派发目标也可继续，原有独立停止不会解除。控制台在目标确认中明确提示这一点；不为其他计划新授予权限。

发布 MR、合并、额外网络/凭据权限、保护目录访问、计划范围扩张仍按原规则处理。取消/停止始终有效；不能因为自动启动或重启复用而释放独立人工 hold。

## 3. 数据模型与兼容

- `Plan.workflow` 为可选对象，包含 `automaticHandoffs`、`materialPaths`。新建计划默认开启受限自动交接，资料默认为空；持久化旧对象无该字段时视为旧流程。
- 创建计划的成员支持 `reviewRequired`（默认 false）；最终集成节点无论该值如何，都保留人工最终验收。
- 计划授权指纹覆盖 workflow 和成员里程碑。旧计划缺少这些字段时不改变其既有指纹结构。
- 资料快照按计划保存，记录源路径、内容哈希、大小和固定快照路径；成员只收到只读快照，不得到任意外部磁盘读取权限。
- 自动接受结果记录 `acceptedBy: coordinator`；普通人工接受记录 `acceptedBy: human`。旧记录仍可读取。
- 继续使用现有 JSON 实体存储，不破坏现有数据库 schema，不重置或重写历史任务。

## 4. 统一计划启动

1. 主 Agent 使用现有 `project_open` 绑定当前项目并按需启动本地服务，创建含工作流说明的任务图；不另造调度器。
2. `plan_start` 仍生成授权请求；面板也可直接选择计划“确认启动/恢复”，不需要先申请再去另一页面。
3. 可信管理端按当前计划 revision/授权指纹确认。新工作流先运行真实环境检查，再为明确列出的资料生成快照。
4. 所有准备工作成功且状态仍未改变后，在同一数据库事务中启用受限本地运行时（已启用则复用）并批准当前计划。
5. 任一准备失败均不得派发模型；计划保持未获本次授权。失败恢复使用相同 requestId；不能盲目创建新的执行轮次。
6. 文件系统快照与数据库无法成为一个事务，使用预备快照与清理逻辑；数据库失败删除本次未引用的快照，已有有效快照不能被删。

批准不等于每个成员立即运行。依赖、并发、资源、人工 hold、到期时间和预算继续由现有 scheduler 检查。

## 5. 运行时授权跨重启

重启仍增加 fence、废弃旧执行许可和旧预览，旧进程/未知副作用仍需对账。但不立即销毁已批准且未过期的 enablement：

- 服务启动后自动检查；检查成功、fingerprint 完全相同、没有 quarantine/未知操作时，更新授权绑定的 daemonEpoch，不延长 expiresAt。
- 检查前不得执行。指纹变化、验证中断、清理不确定、人工禁用和到期均不得恢复。
- 这是恢复原授权，不是新建永久项目授权。配置/技能/工具链变化仍可能需要在下一次目标确认中重新授权。

## 6. 资料自动分发

不从任意任务文字自动扫描路径，不允许 Worker 请求任意文件。主 Agent 只把用户明确给出的文件加入 `materialPaths`，在计划确认中统一展示。

可信服务确认后读取普通文件并生成不可变快照，继续执行现有保护目录、symlink/真实路径、文件大小和总量检查。每计划最多 10 个文件、合计 32 MiB；每任务仍执行 50 文件限制。源文件后续变化不悄悄改动既有快照。

资料快照作为各成员的只读 reference 挂载，保持已审批技能/工具链配置不变。附件不是授权、也不是指令来源。旧任务逐个附加机制保留用于诊断/显式补充，但不再作为新计划的必走步骤。

本次不自动安装任意技能、不继承整个主 Agent HOME/凭据、不开放整个外部目录。PDF 等能力仍来自已配置能力包；缺能力时明确报告缺项。

## 7. 自动交接、业务里程碑与最终交付

协调服务在执行结束及持久化 effect 已完成后检查可交接节点，必须同时满足：

- 当前工作流已获有效授权，计划未暂停/停止/完成，成员没有 hold、失败、对账或新待处理输入；
- 当前 report 为 ready、没有 question，checks 非空；最近 assignment 已结束，依赖输入仍匹配；
- 不是最终集成节点，也不是 reviewRequired 节点；出边全部是 artifact；不存在 MR、待审批和未完成副作用。

通过后由协调服务接收 report.summary 与 checks 的结构化交接内容，保存哈希并审计。该动作表示“可供下游使用”，**不宣称测试证据已由人独立验证**，UI 必须区分。

代码依赖仍需要原有绑定 MR 的合并 commit 与本地基线验证；本次不把未合并代码偷偷降格为 artifact，也不自动 publish/merge。报告自述不能越过代码验收。

最终节点和人工里程碑保留人工确认。最终结果被接受且全部成员满足原有 complete 条件时，同一次操作完成计划，避免再按“确认整体交付”。

## 8. 人工控制与中途调整

新增管理端 `human-control` 接口：复用现有 Engine 的状态校验、申请与批准逻辑，在单次可信人工请求中完成。请求有 requestId 和 expectedRevision；相同请求幂等，变更内容重用 ID 被拒绝。额外重试仍只绑定下一轮 assignment，不扩大自动预算。

公开 bridge/MCP 调用该管理接口必须失败。MCP 的 task_retry 超预算仍产生待审批；人点击控制台重试则已是人工决定，不再要求第二次批准。

运行中调整范围继续使用现有 task_adjust 的停止、清理、保留历史、作废旧授权逻辑；新范围通过统一计划确认恢复，不增加另一套解锁步骤。独立 hold 不能被计划恢复顺手清除。

## 9. 有界恢复与 UI

环境预检由服务自动执行。对已确认在发送模型前取消的准备操作，沿用同一 assignment，按失败计数退避；达到上限后停在明确的恢复阻塞原因，不能不断耗时/刷屏。未知进程、模型已发送或发布阶段不走此恢复分支。

已确认进程清理成功的暂时性启动/连接失败，会挂起派发并重做环境检查；同指纹、未过期的原授权不因此作废或延期。真正的权限/配置变化仍撤销授权。第一次和第二次准备取消分别至少等待 1 秒和 2 秒，第三次停止为明确失败。外部资料缺失等确定性错误不反复自动重放。

面板默认计划视角，保留依赖图和阶段结论。人工控制按 stage 过滤：运行中不显示启动/重试，计划成员未获计划授权时引导确认整个计划。可信普通控制用确认按钮，不再抄写 UUID；高风险发布/环境权限扩展的详细确认保留。

健康环境只显示简短状态和可展开诊断；异常显示一个行动原因。资料列表、自动交接规则与人工里程碑放在同一计划确认中。真实环境检查失败不隐藏。

## 10. 实施顺序与回归

先写本文，然后按以下顺序实现：

1. 计划工作流字段、兼容的授权指纹、自动 artifact 交接及审计。
2. 计划资料快照与统一可信启动；直接人工控制和幂等。
3. 跨重启授权复用、有界准备恢复。
4. 控制台精简、插件说明及使用文档同步。
5. 构建、单测和安全回归，不操作用户生产任务、不发送真实付费模型轮次、不自动发布或提交。

必须覆盖：新/旧计划兼容；artifact 解锁下游；人工里程碑/最终节点/代码边不自动接受；输入变更、暂停、hold、过期、待审批不自动交接；文件来源保护、共享快照、失败清理；单次可信审批、重复请求/版本冲突、bridge 越权拒绝；原预算外人工追加仅一轮；重启保留到期时间，指纹变化/禁用/未知执行不复用；准备退避到上限停止。

## 11. 本次明确不承诺

不伪造宿主的人类身份，不取消首次目标确认；不自动安装任意工具；不自动合并代码；不保证任意业务任务都能成功；不把单测通过说成真实 Worker 已跑通。安装和重启真实项目需单独说明，不在源码修改时静默切换生产服务。
