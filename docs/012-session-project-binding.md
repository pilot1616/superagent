# 按会话项目绑定插件

## 问题与范围

上次本机安装把 MCP 的 `--state` 固定为 insight-plugins1 实例，导致全局可用不等于管理当前会话项目。本次改为“用户级插件 + 会话级绑定 + 项目级独立服务”，不改变任务图、审批、执行门禁，不将多个仓库塞入同一个原单仓库数据库。

## 确定契约

1. 通用 MCP bridge 不带 `--state`，可带 `--projects-root` 指定本机项目宿主目录；显式 `--state` 保留为兼容的单实例模式。
2. 每个 MCP 连接初始未绑定，新增 `superagent_project_open`。必须传入来自真实会话上下文的绝对项目路径，不使用 MCP 进程 cwd、不读取全局“最近项目”、不回退旧仓库。子目录解析为所属 Git 根。
3. 宿主提供 MCP roots 时，所选 Git 根必须匹配至少一个 root 所属 Git 根；每次调用重新验证。多 roots 必须明确选择。宿主不提供 roots 时，只能使用主对话明确取得的当前项目路径；Skill 必须询问缺失的路径，不能假称自动检测。
4. 一个连接只绑定一个项目。并发会话分别绑定不同项目；同项目共享已有服务。不同项目的 state、SQLite、worktrees、审批、面板登录令牌均隔离。项目/任务 ID 不会触发跨实例路由。切换项目需新会话，宿主 roots 改变后旧绑定拒绝操作。
5. `project_open` 是显式启动本地协调服务的入口，不是 Worker 执行授权。首次初始化需要 `initialize=true`，以及显式 model 或本机设置的 defaultModel；不读取账号、不复制认证。未指定初始化时不存在的项目返回明确 setup-required，不默默建环境。
6. 本机宿主设置仅存默认模型和旧实例映射，不设默认仓库。新项目按 canonical Git 根的哈希确定独立目录；setup/start 用每项目文件锁串行化。已有目录不覆盖，残留锁/不确定初始化需人工检查，不自动删除。
7. 显式打开时连接健康服务；若服务未运行且不存在 daemon.lock，可启动独立 `serve --with-panel`。有锁但不可连接时拒绝盲目重启。跨会话使用 detached 服务；关闭对话不关闭其他会话的服务。
8. 新项目服务带独立随机端口控制台，返回对应 URL 和私有 token 文件路径，不返回 token。服务关闭时面板一起关闭。旧实例可映射原 state 与已存在控制台 URL，保留任务和审批，不搬数据库。
9. 安装脚本支持项目模式，生成本机 Node/CLI 绝对路径；旧 `--state` 仍可显式使用固定模式。用户授权后更新本机插件副本、cachebuster 并重新安装。已有会话需重新开始，不声称热替换工具已生效。

## 验收

- 两个 MCP 客户端分别选择 A/B，建单、列单、health、审批与面板地址不串；第三客户端选择 A 复用。
- 未选择、错误 root、多 root 不明确、非绝对路径、无模型初始化、同连接切换、当前 roots 改变均拒绝。
- 首次初始化严格显式、同项目并发初始化不覆盖；服务有锁但不可达不盲目重启。
- 旧 insight-plugins1 映射不成为任何会话默认；其任务和审批保留。
- 实际插件重新安装和从不同 cwd 发起 MCP 初始化/health；不发起真实模型 turn，不批准任何真实任务，不启用 GitLab 写入。
