# 任务与计划删除

## 目标与边界

- 人工控制台提供独立任务删除和整组计划删除，清理草稿及已经停止、失败、完成的任务。
- 持久化逻辑删除：从任务/计划列表、调度、上下文订阅中移除；在同一 SQLite 事务内保留删除前快照及审计。不是敏感资料擦除，也不释放工作区磁盘空间。
- 不删除 Git 分支、worktree、用户文件、参考资料、Worker 会话或远端 MR。
- 本次只增加能力，不删除用户现有任务，不自动重启业务服务。

## 删除规则

1. 仅已登录控制台（Cookie、Origin、CSRF 校验）及可信交互式 CLI 可执行，不增加模型可直接执行删除的 MCP 工具。
2. 显示影响范围和保留内容，用户输入“删除”确认。服务端要求目标 ID、当前版本、幂等请求 ID。
3. 运行、排队、停止、待核对、有未完成副作用或未清理子 Agent 的任务不可删除；先停止并完成核对。
4. 计划成员不能单独删除。整组删除校验计划版本、全部成员 ID 和成员版本；任一成员不安全则整组不删除。
5. 过期未决审批、解除订阅、交还拥有事件，保留历史投递事实；无其他任务拥有的事件可重新路由。
6. 同请求重复提交返回同一回执；旧版本及幂等 ID 内容冲突拒绝。重启不能复活或派发已删除任务。

## 实现与验收

- `core/src/deletion.ts`：schema、原子归档删除、依赖/活动检查、共享上下文清理、幂等与审计。
- `storage/src/store.ts` / `core/src/ports.ts`：限定的任务和实体移除，无文件删除。
- `service/src/daemon.ts` / `panel-actions.ts` / `cli.ts`：管理员入口与交互式确认。
- 控制台：任务详情及计划详情删除入口，成功清空选中项并刷新，失败保持原状态。
- 测试覆盖独立任务、重开数据库、完整计划、活动/版本/依赖阻断、事务回滚、共享上下文、幂等、认证、CSRF 和 bridge 禁止删除。
- 构建、针对性和完整包测试通过。测试使用临时数据，不动真实任务。
