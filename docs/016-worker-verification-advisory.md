# Worker 验收门槛移除

日期：2026-11-18。按用户要求，移除插件中阻止 Worker 派发的完整验收前置条件。

本说明修订 014/015 的运行准入规则；其余任务审批、权限边界、恢复和验收缺口说明仍有效。

## 行为变化

- `evaluateRuntime` 不再将缺少、失败、过期的完整验证记录加入派发阻塞原因。
- 环境检查有效且认证已配置后，运行时进入 `ready`，无需先运行 `runtime verify`。
- 控制台“预览并启用”或可信终端 `runtime enable-preview/enable` 允许没有 `verificationId` 的启用。
- 启用和 assignment permit 不再依赖验证记录或验证证据文件；没有完整证据时，不写入任何“验收已通过”能力。
- 启用有效期由 `enablementMaxHours` 决定，不再被验收有效期截断。
- 缺少完整有效证据显示 `RUNTIME_VERIFICATION_INCOMPLETE`；总 token 上限缺失显示 `TOKEN_BUDGET_NOT_ENFORCED`。这两项是警告，不是停止派发的条件。
- 已有证据仍校验完整性；损坏证据不会被宣称通过，但不再影响运行授权。
- 可选验证正在运行时仍暂停生产派发，避免测试和生产并行；验证结束后可以重新人工启用。进程清理不确定仍隔离。
- 修复真实启动时的自触发失效：Worker 进程已经在任务目录启动，不再向 `thread/start/resume` 重复发送 `cwd`（固定版本会因此写入项目 trust 配置，误触发配置变更保护）。改为使用进程工作目录，并校验返回 thread 的目录必须等于任务目录；不关闭配置篡改检测。

## 保留的控制

仍检查项目绑定、运行时版本/profile、独立模型认证、环境检查有效期和环境指纹。仍需人工启用当前项目，且每个任务/计划必须独立获得审批。

保留一次性启用预览、项目确认、版本检查、队列快照、幂等、启用到期和重启失效。保留 humanHold、暂停、停止、依赖验收、资源互斥、并发限制、尝试次数、授权期限、取消及不确定执行隔离。

不修改 Codex 沙箱，不提供权限升级或工具网络授权，不读取/复制主会话凭据，不自动 push、发布 MR 或合并。关闭的服务和运行中的其他项目不因代码更新而自动迁移或重启。

## 使用流程

1. 在目标项目的新会话中使用新版 Superagent；绑定项目，打开其控制台。
2. 如实例仍是旧 service version 2，先按既有流程停服、备份并显式迁移到 version 3。不要手改版本号。
3. 配置项目 Worker 的模型/provider 和独立认证，运行环境“重新诊断”。此操作不提交模型 turn。
4. 环境显示“已就绪，待人工启用”后，点击“预览并启用”，核对项目、待派发任务和费用风险，然后确认。
5. 审批任务或计划；调度器按依赖、资源和并发规则选择任务交给 Worker。

不需要先点击“验证预览”，也不需要将 `VERIFICATION_BUDGET_UNSUPPORTED` 改成通过。

## 不作出的保证

这次修改移除的是插件验收门槛，不代表 V2–V7 或真实多 Worker 验收已经完成。完整验收仍未通过，没有可强制执行的总 token/费用预算。生产执行是否成功取决于当前项目环境、认证、模型及任务本身。

回归测试覆盖无验证记录派发、失败/过期验证、损坏证据、启用预览以及保留的认证/指纹/审批/停止控制。测试夹具不是生产运行证据，不会被写入真实项目 state。

真实 App Server 冒烟测试使用临时 Git 仓库及仅本机回环 HTTP 假 provider，确认实际调度能够创建任务工作目录、启动 Codex、建立 thread 并向 `/v1/responses` 提交请求；假 provider 明确拒绝推理，不使用真实账号、不调用外部模型，也不证明任务完成或真实模型隔离验收通过。
