# Worker 开发能力与控制面隔离

> 2026-11-21：[020](020-centralized-workflow.md) 新增计划级资料声明与统一确认后的共享快照。本文逐任务预览/附加流程仍可用于旧任务或明确补充，不再是新计划的必经步骤；技能与凭据隔离规则保留。

## 1. 目标与边界

Worker 使用与主会话相同的 Codex 引擎，但不是主会话的复制品。模型、技能、工具链、资料、上下文和权限是不同配置。改造提供可审查的开发能力，不复制主会话的完整 HOME、环境变量、MCP、插件、聊天记录或权限。

保留：计划 DAG、依赖验收、任务预算、人工启用、任务授权、停止与对账、独立 worktree、控制台认证及发布审批。网络仍关闭，运行中扩权仍拒绝；任务正文、PDF 和技能不能授予权限。

## 2. 项目级能力配置

新增离线命令 `runtime configure-capabilities --json`。必须先停止项目服务、结束执行并完成不确定操作对账。命令沿用配置锁、备份和审计，保留模型、provider 与子 Agent 配置；生成新 profile，旧 Worker 线程不再复用。重启后重新诊断和人工启用，不继承旧环境授权。

配置输入：

- `skills`：显式选择的技能目录，必须有 `SKILL.md`；不自动启用所有主会话技能。
- `toolchain.pathEntries`：受信任程序目录，优先于基础 PATH；必须是存在的绝对路径。
- `toolchain.readRoots`：工具及运行库需要的只读路径，不能覆盖 HOME、控制状态、其他任务或凭据目录。
- `toolchain.environment`：仅允许 `DEVELOPER_DIR`、`SDKROOT`、`JAVA_HOME`、`VIRTUAL_ENV`、`LANG`、`LC_ALL`；路径变量必须可解析并增加相应只读访问。禁止任意环境继承及 token、代理认证、SSH socket 等变量。

首次创建 profile 时自动检测 macOS 已选中的开发工具目录；已有 profile 不静默变更。配置时也检测 Git，优先使用真实开发工具 Git，而非依赖 `/usr/bin/git` 启动器。`git --version` 在隔离环境下作为无模型诊断运行，失败说明具体工具问题，不能误报为整个宿主缺少 Git。受审查的 PATH 同时显式写入 `shell_environment_policy.set`：仅设置 App Server 进程环境不足以通过 `inherit = "none"` 的 shell 清洗，否则可能误用没有 PDF 库的系统 Python。

技能先复制为受管快照，校验文件数量、总大小、目录循环及链接边界。禁止嵌套链接越出技能源目录、特殊文件和常见凭据/执行配置；导入根链接只在解析为用户明确选择的技能目录后接受。Worker 的用户技能目录指向该代快照，只授予快照只读权限；源目录后续变化不会自动进入 Worker。配置记录快照哈希，启动前复核。

## 3. 任务级资料

新增可信控制面 `task-materials-preview`、`task-materials-attach`、`task-materials-list`，不暴露为公共 MCP 工具。

1. 用户在任务详情填写本地文件绝对路径。
2. 预览解析真实路径并计算名称、字节数和 SHA-256，绑定任务 revision，五分钟有效。
3. 用户输入完整任务 ID 确认；附加前再次读取并验证内容和任务 revision。
4. 文件复制到该任务的受管资料目录。拒绝控制状态、凭据目录、特殊文件和超过限制的文件；不把原文件路径开放给 Worker。
5. 资料清单与审计落库，任务 revision 增加，下一次执行使用新线程。附加本身不启动、重试或授权任务，也不清除原阻塞结论与人类 hold；已验收结果保持不可变，不能再附加新资料。

单次最多 10 个文件、合计 32 MiB；同一任务最多 50 个文件。运行中、停止中、不确定或有待派发执行的任务不能附加，避免修改正在使用的输入。需要先停止任务或等待本轮结束，再附加并显式恢复/重试。

系统临时目录存在平台隐式读写授权，不能用作受保护快照的存储位置。导入技能和附加资料拒绝 state 位于系统临时目录；默认 `~/.local/state/superagent` 满足条件。边界集成测试使用 HOME 下独立私有临时测试目录，而非 `/tmp`。App Server 的旧 `command/exec` 沙箱参数不能代表命名权限，边界测试显式使用 `codex sandbox -P superagent-worker`，技能发现和配置回读另用 App Server 验证。

每个 Worker 仅获得本任务资料目录的只读配置覆盖，不能读取其他任务资料。任务输入携带快照路径、哈希和资料不具授权效力的说明。资料更新不会自动满足任务 DAG 的已验收依赖。

## 4. Git 与 worktree

2026-11-21 按用户选择切换为[信任 Worker 的本地 Git 写权限](023-trusted-worker-git.md)：当前任务对应仓库的 Git common directory 显式可写，Worker 可在分配的分支直接 `git add` / `git commit`。`GIT_OPTIONAL_LOCKS=0` 仅减少只读查询的可选写锁，不禁止显式暂存或提交。任务范围、禁止破坏性操作及不修改其他任务分支由提示词约束，不再声称共享 Git 元数据有强隔离。远端发布保留既有审批流程。

每个进程使用命令行配置覆盖增加资料只读根和本仓库 Git 可写根，不修改共享 profile 文件，因此并行 Worker 的资料权限不串用。启动后通过 `config/read` 精确核对基础策略及本轮覆盖；未声明的 MCP、插件、网络或额外写权限仍导致失败。

## 5. 完整性与诊断

能力配置与技能快照进入 profile 哈希、运行时指纹和启用预览。技能快照变更会拒绝加载；每次执行再次复核资料哈希，资料损坏必须失败，不能静默降级。配置详情在运行环境页面可查看，不把模型凭据返回到页面。

诊断区分 Git 工具链、技能快照、认证、协议和策略错误。真实模型端到端验收仍独立于普通单元测试；测试通过不能冒充真实任务已成功完成。

## 6. 验证

覆盖技能复制与源变更隔离、快照篡改、外链/循环/特殊文件、环境变量白名单、保护路径、任务预览过期/内容变化/revision 冲突、请求重放、任务隔离、只读覆盖、Git 诊断和公共 MCP 禁止访问。使用固定版本真实 Codex App Server 验证技能发现及有效权限，不调用付费模型。
