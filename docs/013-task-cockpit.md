# 人工任务驾驶舱与执行阻塞修正

## 目标与边界

控制台默认展示需要人看的信息，而不是铺开全部任务、UUID 和原始 JSON。保留当前会话项目绑定、独立项目状态、人工审批、不可变验收结果与发布指纹约束。

本次不将未完成的真实 Worker 验收改为通过。现有门禁不是待审批，而是源码中的隔离、审批回路、取消、恢复、认证模型 turn 尚未验收。提供逐项原因和检查入口，并修复门禁关闭时任务仍被取走、随后失败的问题。门禁关闭时保留已批准任务及待执行 effect，显示“等待运行环境”；停止与清理操作仍能执行。协议探测、单元测试和人工批准任务都不能代替真实隔离与认证验收。

控制台提供独立“诊断 Worker 连接与认证”按钮，同源、登录和 CSRF 校验后只检查当前项目的配置、握手与账号是否配置，仅保存脱敏诊断（状态、版本、模型、时间与本地配置路径），不返回凭据。不允许公开 MCP 触发该管理操作，不提供跳过验收开关。

## 人工总览

- 以任务计划为主入口，单任务为补充；审批中心、上下文与底层审计独立展开。
- 任务列表默认只看未完成，支持待我处理、未完成、已结束和全部、标题搜索及服务端分页，每页 10 条。计数覆盖全部匹配记录，不以当前页推断总量。代码已合并但仍待人工结果验收的任务保留在未完成和待我处理，不因 MR 状态提前归档。
- 每行只显示名称、中文状态、最近结论摘要。UUID、输入、执行绑定和审计移入详情折叠区。
- 计划详情以可点击的分层 DAG 展示依赖，边区分产物/代码验收，节点显示状态与已验收标识；同时保留文字关系用于无障碍访问。选中节点打开同一套任务详情。
- 不同项目仍有不同看板，本次不提供跨项目调度。

## 执行中调整

1. “追加说明”调用已有 task_message，展示输入是否待消费；不声称已即时注入正在执行的 turn，也不解除人工停止。下一轮才消费待处理说明。
2. “暂停并调整范围”增加版本化 task_adjust：必填新范围、标题、原因及目标版本，计划成员还必须绑定当前计划版本。支持调整优先级及资源。保留原始范围、结论、输入及变更原因作为审计。
3. 单任务调整时先请求停止旧执行，撤回授权，更新范围，要求清理完成后重新申请恢复和人工审批。保留 workspace，不删除已有编辑；新执行创建新 thread，不能隐式沿用旧授权。执行分配保存启动时的资源快照；调整资源后旧执行在清理、恢复核对期间仍占有旧资源，不提前解锁给其他任务。
4. 计划内调整停止整组，撤销计划授权、递增图版本、作废待审批，并保留独立人工停止。所有未验收成员的旧报告保留为历史、不可继续当作本版结果；重新审批后重新评估这些节点，既有尝试预算不扩大。已验收结果与完成计划不可改写；既有验收结果在依赖快照仍匹配时可继续用于后续集成与整体验收，不因其他节点调整而被强制重跑。依赖拓扑执行后仍不能直接改写，应另建后续计划。
5. 清理未确认、发布中、版本冲突时拒绝变更。不自动恢复或重试。

## 阶段性结论

- 独立持久化 checkpoint，绑定任务与 assignment。报告在自动进入下一轮、重试及调整范围后仍保留。
- 采集 Worker 已完成的 commentary agentMessage 作为“执行中进展”，不采集 reasoning、工具原文或半截 delta；最终结构化报告作为“本轮结论”，包含检查与问题。
- 同一 item/assignment 去重；停止、旧 turn、旧 assignment 的迟到信息拒绝。历史分页读取，最新摘要可见于列表。
- 进展与本轮报告明确标记未验收，不能满足下游依赖；只有既有人工 accept-result 才能解锁依赖。调整范围或计划版本后，列表摘要与时间线显式标为历史，不能仅依靠用户展开详情辨别旧结论。
- 执行失败或不确定状态另存为系统状态记录，避免重试后错误原因消失。每条记录保留当时范围与执行轮次，旧范围结论不能冒充新范围成果。

## 验证与交付

覆盖门禁关闭时 effect 不被消费、过滤与计数、DAG 布局、说明排队、调整撤权与旧版本拒绝、计划内调整与独立停止、旧执行资源在清理与恢复期间的保留（兼容没有资源快照的既有分配）、checkpoint 去重及跨轮持久化、HTTP 认证与 CSRF。构建和全部测试后更新使用说明。控制台静态资源及服务代码需要重启对应项目服务后生效；不自动停止正在执行或仍有不确定状态的实例，不读登录令牌、不替人审批。
